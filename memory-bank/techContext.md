# Technical Context

## Language & Standard
- **C11** (CMAKE_C_STANDARD 11)
- Windows-only, MSVC compiler

## Build System
- **CMake** (minimum 3.20) with NMake Makefiles generator
- Static runtime (`/MT` release, `/MTd` debug) — fully portable binaries
- Warning level `/W4`

## Build Targets
| Target | Type | Source |
|--------|------|--------|
| `j_lib` | Static library | All src/ modules |
| `jc` | Console exe | `main.c` + `j_lib` |
| `j` | Windows GUI exe | `main_win.c` + `j_lib` |
| `j_tests` | Console exe | All test files + `j_lib` + cmocka |

## Linked Libraries
- `advapi32` (registry)
- `shell32` (ShellExecuteA)
- `user32` (window management, OSD)
- `gdi32` (text rendering for OSD)

## Diagnostic Logging
- `jc --log` creates `%TEMP%\jump_log.flag` (one-shot flag)
- Next invocation detects flag, writes to `%TEMP%\jump.log`, then deletes flag
- `--log` does NOT read config/cache — safe for debugging bootstrap issues
- Log IDs: `JMP`=jump.c, `CFG`=config.c, `CAC`=cache.c, `RES`=resolver.c, `TC_`=tc.c, `LOG`=log.c

## Test Framework
- **cmocka** 1.1.7 (fetched via FetchContent, static linking)
- Test binary: `j_tests.exe`
- Run via CTest

## Build Scripts
| Script | Purpose |
|--------|---------|
| `build_env.ps1` | Sets MSVC x64 environment (compiler/SDK paths), generated by setup_dev.ps1 |
| `configure.ps1` | `cmake -B build -G "NMake Makefiles" -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON` |
| `build.ps1` | `cmake --build build` |
| `test.ps1` | `ctest --test-dir build --output-on-failure` |
| `check_coverage.ps1` | OpenCppCoverage with 85% gate |
| `setup_dev.ps1` | Full dev environment setup (requires Admin) — installs Chocolatey, Git, CMake, OpenCppCoverage, VS Build Tools |

## Dev Setup Flow

### First-Time Setup (or Broken Environment)
Run from an **elevated (Administrator)** PowerShell prompt:
```powershell
.\setup_dev.ps1
```
This script is the single command to go from a bare Windows machine to a working build. It performs 7 steps:

| Step | What it does |
|------|-------------|
| 1 | Installs **Chocolatey** (if missing) |
| 2 | Installs **Git**, **CMake**, **OpenCppCoverage**, **VS Build Tools 2022** via Chocolatey (skips already-installed) |
| 3 | Auto-detects MSVC toolset + Windows SDK versions, generates `build_env.ps1` |
| 4 | Configures CMake (`cmake -B build -G "NMake Makefiles" -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON`) |
| 5 | Builds the project |
| 6 | Runs all tests |
| 7 | Runs coverage gate (85%) |

### What `build_env.ps1` Does
- Generated by `setup_dev.ps1` — sets MSVC x64 environment variables (`PATH`, `INCLUDE`, `LIB`)
- All build scripts (`build.ps1`, `configure.ps1`, `test.ps1`) call it as a prefix
- Contains hard-coded paths to the detected MSVC and Windows SDK versions
- **If builds break after a VS update**: re-run `.\setup_dev.ps1` to regenerate it

### Troubleshooting Build Failures

| Symptom | Cause | Fix |
|---------|-------|-----|
| `cl.exe` not found | `build_env.ps1` missing or stale | Run `.\setup_dev.ps1` as Admin |
| `cmake` not found | CMake not installed or not in PATH | `choco install cmake --installargs '"ADD_CMAKE_TO_PATH=System"' -y` |
| NMake errors / linker errors | MSVC paths changed after update | Re-run `.\setup_dev.ps1` to regenerate `build_env.ps1` |
| `build/` folder corrupt | Stale CMake cache | Delete `build/` folder, then `.\configure.ps1` + `.\build.ps1` |
| Tests fail to compile | cmocka fetch failed | Check network, delete `build/`, re-run `.\configure.ps1` |
| OpenCppCoverage not found | Not installed | `choco install opencppcoverage -y` |
| `build_env.ps1` has wrong paths | VS or SDK version changed | Re-run `.\setup_dev.ps1` as Admin |
| Script requires Admin | `setup_dev.ps1` has `#Requires -RunAsAdministrator` | Right-click PowerShell → Run as Administrator |

### Prerequisites (Manual Install)
If you prefer manual setup instead of `setup_dev.ps1`:
1. **Visual Studio Build Tools 2022** with C++ workload
2. **CMake** ≥ 3.20 (in PATH)
3. **Git** (in PATH)
4. **OpenCppCoverage** (optional, for coverage gate)
5. Create `build_env.ps1` manually — set `$MSVC_DIR`, `$WINKITS_DIR`, `$WINKITS_VER` to match your installation

### Daily Build Commands (after setup)
```powershell
.\configure.ps1          # CMake configure (only needed once or after CMakeLists.txt changes)
.\build.ps1              # Build (runs configure first via task dependency)
.\test.ps1               # Run tests
.\check_coverage.ps1     # Coverage gate (85%)
```

## Coverage Configuration
- **Gate threshold**: 85%
- **Excluded from coverage**: `osd.c`, `main.c`, `main_win.c`, `jump.c`, `install.c` (UI/orchestration code)
- Tool: OpenCppCoverage

## Test Fixtures
- Located in `tests/fixtures/` — various INI files for testing edge cases
- `tests/demo/` — directory tree simulating a real user config setup
- `FIXTURES_DIR` macro defined at compile time for test access

## Dependencies
- No runtime dependencies (statically linked)
- Build-time: CMake, MSVC (Visual Studio Build Tools 2022), cmocka
- Coverage: OpenCppCoverage (optional)
